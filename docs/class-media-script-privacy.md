# Class recording script privacy rollout

Class media manifests and audio chunks stay playable by class learners; ordinary recordings marked public also remain playable from printed QR codes. AI-generated audio keeps its existing audio access setting. Ordinary and AI-generated recording transcripts live in `classes/{classId}/mediaScripts/{mediaId}`. Firestore rules let a class teacher read that document and reject learners and unsigned visitors. The script release callable also rejects view-as sessions. New class media writes reject a public `script` field.

The `mediaScriptAccess` callable checks the saved lesson item, task, class membership, account suspension, and actual media placement. Hidden returns no script. Karaoke and Show with button return the transcript to an authorised learner. After listening gives the browser a session when playback starts and releases the transcript after the recording's saved duration. This server-timed gate prevents an immediate direct read, but it **does not prove that the person listened**: a modified client can start a timer without playing audio. Classroom trust and audio playback restrictions still apply.

Printed QR codes receive an opaque teacher-issued grant tied to a task and recording, even when the teacher prints before showing or unlocking it. A QR can play the public audio without a grant; the transcript remains unavailable. Script access checks the task’s current visibility: hiding, locking, restricting or removing the task denies transcript access, and showing or unlocking it allows the saved mode to take effect. A single recording used in multiple tasks receives the strictest printed mode, so its printed script may be unavailable when placements disagree. A recording placed in a visible Karaoke/Button task is available through that task even if another task hides the same recording; make a separate media copy when those audiences must differ. Share documents and their media copies are teacher-only under `shareOk`; teacher-to-teacher copies retain editable scripts. Learners cannot read them. Standalone offline HTML includes Karaoke/Button scripts only when every exported placement of that recording allows them. It omits Hidden and After scripts because its payload is readable without an online release check. It warns that After scripts are available online.

## Release sequence

1. Merge and deploy the AI recording privacy prerequisite (#309) first. Wait for its complete deploy before this release. Run the class script emulator test in PR checks and deploy checks, then deploy hosting, Firestore rules, all functions, and scheduled cleanup together. Check that `mediaScriptAccess`, `issueMediaScriptQr`, and `clearMediaScriptSessions` are present in the deployed function list; check the scheduled cleanup job is enabled. `mediaScriptSessions.expiresAt` alone does not delete records.
2. Run **Audit class media script migration** with Apply off. Record `legacyScripts`, `withText`, `invalidScripts`, `conflicts`, and `errors` without logging transcript contents. This scans all class media manifests, not teacher-only archives or shares. An unexpected non-array script blocks the apply step so its data is never discarded.
3. If conflicts or errors are nonzero, inspect privately. If clear, rerun the workflow with Apply on and the exact reviewed `legacyScripts` count. It repeats the preflight, writes the private copy, verifies it, and removes the unchanged public field in a transaction. Run a second dry run and require `legacyScripts: 0`. If the count changed between runs, review again. The migration is idempotent.
4. On the published build, use a signed-in teacher and learner to create an ordinary recording with a distinctive harmless sentence, add it to an unlocked task, and test Hidden, Karaoke, Show with button, and After listening. Check the learner-readable media manifest has no `script`; the teacher can still edit the transcript. Test a printed QR with a second browser, a hidden or locked task, a revoked learner, and an offline HTML download. Record whether a complete audio play and the intended transcript behavior worked. Do not mark B-030 Live until this and migration are verified.

Lesson/task copies and lesson bundles now stop with an error if a private script read fails, before creating an incomplete lesson or task. A recording with no private script document can still be copied. Offline HTML also stops when a visible Karaoke/Button script cannot be read; its download screen reports the error. The player tolerates a temporary script read failure so audio remains usable. The printed teacher answer key still includes a selected recording's script. A temporary private-script read error can leave that key without a transcript, though the QR audio continues; retry the export after connectivity returns. A standalone offline file cannot deliver a controlled After listening transcript. If an existing recording's public manifest was already copied into an old offline file or downloaded before migration, that copy cannot be recalled.
